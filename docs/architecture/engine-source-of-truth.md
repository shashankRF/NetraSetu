## Legacy paths and data handling

- `Backend/risk_integration.py` was the old independent keyword-to-risk adapter. A repository-wide Python import search found no active application caller; `rag/orchestrator.py`, its only importer, was itself unreferenced and was removed. Active application orchestration uses `risk_integration_v2.py`. The unused module was removed so there is no second active decision adapter.
- `rag/orchestrator.py` was a second, unimported orchestration path with a stale call to the removed risk adapter and a signature-mismatch fallback. A repository-wide import search found no callers, so it was removed. The active top-level orchestration is `Backend/orchestrator.py`, which uses the shared `rag/retrieval.py` interface. The RAG retrieval and index files are active dependencies and were not deleted or rebuilt.
- `rag/multi_kb_retriever.py` points to the configured MAIN, DEFENCE and MARITIME chunk, vector and FAISS files. It checks vector/chunk counts but no content-hash manifest currently binds those artifacts to source versions/model/config. No index rebuild was performed; adding verifiable index manifests remains unresolved.
- No general retrieval cache or scenario-result cache was found in the active run path. Dashboard latest-run state is in memory. It is now cleared before a new scenario request, and successful results expose a run ID and a SHA-256 input fingerprint over the selected query, jurisdiction, scenario, retrieval settings and retrieved passage hashes. The audit entry stores the same fingerprint.
- Performance stage timings already emitted by the pipeline remain the source for internal processing stages. The browser duration remains labeled separately as browser request duration and must not be described as telecom network latency.

## Known gaps

1. Chunk and embedding/index provenance has no complete manifest with source hashes, embedding model revision, preprocessing version, and index build fingerprint.
3. Successful evidence runs have run/input fingerprints; early blocked requests and failed runs do not yet have a full fingerprint contract across all error paths.
4. Full latency instrumentation across browser, retrieval, reranking, evidence, simulation, governance, synthesis and persistence should be checked against the actual existing `performance` payload before adding any timing field; no unavailable stage should be shown as zero.
